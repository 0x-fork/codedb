# CodeDB 0.2.5861

Reduces macOS watcher idle CPU on local APFS/HFS projects and requires verified installer downloads.

The watcher uses recursive FSEvents, probes at most 64 known files every two seconds, and audits directory metadata every 60 seconds. Excluded-file churn is filtered before the bounded event queue. Dropped history triggers recovery. Aliases, foreign volumes, unsupported filesystems, and unavailable streams retain conservative kqueue/polling. Each MCP client still owns its watcher; exact-metadata collisions can take longer to discover on large trees.

The installer requires exactly one valid SHA-256 manifest entry and a working hash tool before replacing the existing binary. Verification failures preserve the old installation and client settings. The installed hook no longer recommends the removed edit tool.

This integrates watcher PR #758 and installer prerequisite #759 onto current main. The hosted-default model and retrieval behavior from 0.2.5860 are preserved. No hosted or paid evaluation was needed for this watcher change.

CPU percentages use process CPU-time delta divided by elapsed time; 100% is one core. These short synthetic runs are diagnostic measurements, not acceptance on the reporter's proprietary 16k-file tree. Other local checks ran during portions of the evaluation.
